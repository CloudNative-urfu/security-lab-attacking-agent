# Design

## Context

Домен за портами. Исследующий агент переиспользует `LLMProxy` (под собственным бюджетом),
`CampaignConfig` (валидация/freeze/публичная проекция). Он НЕ исполняет инструменты против
СС сам — только предлагает конфигурацию для утверждения.

## Goals / Non-Goals

**Goals:** валидный черновик КИК из предложения модели; отделение приватного контекста от
атакующего; собственный бюджет; явное утверждение оператором.

**Non-Goals:** автоматическое исследование произвольного СС «под ключ»; реальная модель
(тесты на fake LLM); автозапуск кампании без оператора.

## Decisions

**D1. Предложение модели валидируется доменом.** LLM возвращает структурированный черновик
(секции КИК); агент прогоняет его через `CampaignConfig.from_raw` (та же валидация и запрет
сырых секретов). Невалидное предложение отклоняется, а не «чинится» молча.

**D2. Приватность.** В черновик переносятся только разрешённые публичные параметры;
admin-credentials/внутренние измерения не попадают в публичную проекцию (используется
существующая `public_projection`).

**D3. Собственный бюджет.** Подготовительные вызовы идут через `LLMProxy` с отдельным
admin-счётом; они не тратят бюджет кампании.

## Risks / Trade-offs

- [LLM предложит небезопасную/расширенную область] → валидация + явное утверждение оператором;
  freeze только после approve.
