# Design

## Context

Сущность Strategy уже определена в памяти, но не использовалась. Библиотека — это
usable-слой поверх неё: курируемый набор техник с фильтром области и ранжированием
(переиспользуем `TokenOverlapScorer`). Это не заменяет PREPARE→COMMIT семантической памяти,
а даёт отдельный лёгкий путь курируемых стратегий.

## Goals / Non-Goals

**Goals:** стратегии с условиями/статистикой; ранжированный scoped-поиск; внедрение в
контекст как доверенная подсказка; обучение по исходу. Backward-compatible с оркестрацией
(библиотека опциональна).

**Non-Goals:** реальная модель (тесты на fake); автогенерация стратегий из воздуха —
стратегии записываются явно (оператором/по исходу).

## Decisions

**D1. Отдельный порт `StrategyStore`.** Лёгкий append + list по области; ранжирование в
`StrategyLibrary`. Не тащим стратегии через candidate/commit знаний.

**D2. Доверенность.** Стратегии — из нашей БД, поэтому идут в контекст как доверенная
секция (отдельно от блока недоверенных данных СС). Полномочия всё равно проверяет харнес.

**D3. Обучение.** `note_outcome(strategy_id, supported)` инкрементит счётчики; ранжирование
при равенстве релевантности предпочитает стратегии с большей долей успеха.

## Risks / Trade-offs

- [Переобучение на ранних данных] → ранжирование в первую очередь по релевантности, доля
  успеха — лишь тай-брейк; порог не жёсткий.
