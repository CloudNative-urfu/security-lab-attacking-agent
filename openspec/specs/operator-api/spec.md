# operator-api Specification

## Purpose
Операторский интерфейс: командный путь (start/pause/resume/fork) и read-модели. Команды
изменения идут через контроллеры и действующие ограничения, а не прямой правкой БД; доступ
авторизуется.

## Requirements

### Requirement: Команды идут через контролируемый путь

Команды кампании (start/pause/resume/fork) SHALL приниматься с command_id и записываться в
outbox в одной транзакции с доменным изменением. Повтор команды с тем же содержимым MUST
возвращать прежний результат; тот же command_id с другим содержимым MUST давать CONFLICT.

#### Scenario: Идемпотентный повтор команды

- **WHEN** команда с тем же command_id и содержимым доставлена повторно
- **THEN** возвращается прежний результат без второго запуска

#### Scenario: Конфликт по command_id

- **WHEN** приходит тот же command_id с другим содержимым
- **THEN** возвращается CONFLICT

### Requirement: Read-модели и авторизация

Read-эндпойнты SHALL отдавать проекции (состояния, память, метрики) только после проверки
авторизации и scope. Секреты, исходники и сырые payload MUST NOT экспортироваться по
умолчанию; UI/экспорт MUST NOT писать в доменные таблицы напрямую.

#### Scenario: Неавторизованный запрос отклоняется

- **WHEN** read-запрос приходит без валидной авторизации
- **THEN** возвращается 401/403 и данные не отдаются

#### Scenario: Экспорт не содержит секретов

- **WHEN** оператор экспортирует проекцию
- **THEN** в выгрузке отсутствуют секреты и сырые payload
