# llm-proxy Specification

## Purpose
Единый доверенный доступ к LLM: вызов только после допуска, без скрытых retry/fallback,
с учётом фактического расхода и валидацией структурированного ответа.

## Requirements

### Requirement: Вызов модели только после допуска и с учётом расхода

LLM-запрос SHALL выполняться только после выданного допуска (reserve/permit) и его usage
SHALL учитываться тем же ledger. Расход (токены/деньги) MUST фиксироваться как Decimal по
фактическим данным ответа.

#### Scenario: Запрос без допуска отклоняется

- **WHEN** инициируется LLM-запрос без действующего permit
- **THEN** запрос не отправляется и возвращается ошибка допуска

#### Scenario: Usage учтён в ledger

- **WHEN** модель вернула ответ с usage
- **THEN** расход нормализуется в Decimal и settle по соответствующему attempt учитывает его

### Requirement: Нет скрытых повторов и fallback

Proxy SHALL явно отключать provider/router retries и fallback; каждый реальный новый вызов
модели MUST учитываться харнесом как отдельная попытка. Число переходов графа MUST NOT
подменять денежный и токенный бюджет.

#### Scenario: Повтор — это новая учтённая попытка

- **WHEN** харнес решает повторить LLM-запрос
- **THEN** создаётся новый attempt_id с новым допуском, а не бесшумный retry внутри клиента

#### Scenario: Скрытый fallback не выполняется

- **WHEN** основной провайдер возвращает ошибку
- **THEN** proxy не делает автоматический fallback на другого провайдера без нового допуска

### Requirement: Валидация структурированного ответа

Структурированный ответ SHALL валидироваться по схеме; при несоответствии возвращается
INVALID_OUTPUT. Смысл результата проверяет инициатор, не парсер. Исправление невалидного
ответа — отдельная учтённая операция.

#### Scenario: Невалидный ответ помечается INVALID_OUTPUT

- **WHEN** ответ модели не соответствует требуемой схеме
- **THEN** возвращается INVALID_OUTPUT, а не молчаливое принятие

#### Scenario: Исправление ответа учитывается отдельно

- **WHEN** выполняется повторный запрос для исправления формы ответа
- **THEN** он учитывается как отдельная попытка с собственным расходом

### Requirement: Durable журнал попыток модели

LLM Proxy SHALL вести durable журнал по (op_id, attempt_id). Повторная обработка той же
попытки MUST возвращать записанный ответ без нового физического вызова провайдера; новый
физический вызов требует новой попытки (attempt_id) и нового допуска.

#### Scenario: Повтор попытки не вызывает модель повторно

- **WHEN** proxy.request обрабатывается повторно с тем же (op_id, attempt_id)
- **THEN** возвращается ранее записанный ответ, а провайдер не вызывается второй раз
